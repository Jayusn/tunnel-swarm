# 地面滤波与跨帧动态检测设计

## 目标

在当前 `camera_init` 世界坐标输入下，解决贴地启动时地面噪声干扰、动态目标在启动预热阶段静止后再运动时漏检，以及动态点被写入持久静态地图造成残留的问题，同时保留当前严格的 3 米天花板过滤。

## 已确认的现状

- `/cloud_registered` 和 `/Odometry` 都使用 `camera_init`，其 Z 轴由定位系统重力对齐。
- 当前动静态判定依赖 UFOMap 的 `seenFree`：先分类，再把整帧输入点写入 UFOMap。
- 当前没有地面滤波；仅有输入点 `z < 3.0 m` 的天花板过滤。
- 预热阶段不是现有检测机制的一部分，`classification_start_frame` 只用于轨迹类别证据累计。
- 当前目标输出由当前帧聚类和跨帧跟踪生成；固定杆应保持静态，移动球应输出动态目标。

## 设计

### 1. 地面平面估计与滤波

利用 `camera_init` 的重力对齐特性，把地面建模为水平平面 `z = ground_z`，而不是使用固定世界高度或“地面上下删除一段高度”。启动初期在传感器附近的点云中对低高度点做高度直方图估计，连续收集稳定样本后锁定 `ground_z`。

对每个输入点只在其到地面平面的距离小于可调噪声容差时删除。默认容差为 0.05 m，表示地面平面内点判定容差，不表示删除地面以上 5 cm 或 8 cm 的所有点，因此直径约 0.3 m 的球上部点和低矮非地面障碍物仍保留。

如果启动阶段没有足够的地面候选点，暂不应用地面滤波，并通过日志保留可诊断状态；不引入新的外部依赖。

### 2. 预热与跨帧运动检测

默认使用 30 帧作为预热窗口。预热期间不向聚类器和跟踪器发布有效动态目标，但仍保存经过天花板/地面/距离预处理后的当前帧点云快照。

预热结束后，除 UFOMap 的 `seenFree` 候选外，增加轻量的跨帧点邻域运动候选：当前点在上一帧附近没有足够近的对应点，但在较大的搜索半径内仍能找到上一帧点，说明该点团可能发生了位移。候选仍交给现有体素聚类和轨迹确认，固定杆的点若只随定位噪声小幅变化不会通过位移阈值；预热时静止、之后移动的球会在开始位移后的后续帧进入候选。

跨帧检测只作为当前 `seenFree` 检测的补充，不改变 `/ldop/dynamic_objects` 的对象级接口，也不把单帧噪声直接作为稳定目标发布。

### 3. 静态地图积分保护

在生成当前帧动态掩码后，只把未被当前帧动态候选命中的点积分到 UFOMap。UFOMap 仍然是持久背景地图，但动态候选不会继续污染它；动态点离开后，背景点重新出现时可以恢复自由空间证据。

`/ldop/static_cloud` 和当前帧静态 Marker 只包含最终静态掩码中的点；`/ldop/dynamic_cloud` 包含 `seenFree` 与跨帧运动候选的合并结果。

### 4. 参数与边界

新增参数集中放在 `config/ldop.yaml`：地面估计帧数、候选半径、直方图分辨率、地面平面容差、预热帧数、跨帧近邻匹配半径和运动搜索半径。所有参数在代码中做正值和上下界收束。

该方案假设 `camera_init` 的 Z 轴保持重力对齐、通道地面基本水平；如果目标完全静止，系统不会把它误报为动态，这是动态检测的语义要求。移动幅度低于跨帧匹配容差时，需通过配置调小匹配半径，而不是扩大地面删除范围。

## 验证

按照用户要求不执行自动化测试。验证内容为：

1. 远程 `catkin build ldop --no-status` 成功。
2. 远程实际参数包含 `z < 3.0`、地面滤波和预热/跨帧参数。
3. 重新启动 LDOP 后确认 `/cloud_registered`、`/Odometry` 和 `/ldop/dynamic_objects` 持续发布。
4. 运行观察顺序：空场景预热；小球预热期间静止；之后移动小球；确认球框出现、固定杆不持续误报、球离开后动态点不残留。
