# 动态目标短时轨迹预测实施安排

## 目标

LDOP 第三阶段的目标是在 LDOP 第二阶段稳定跟踪输出之上，构建独立的动态目标短时轨迹预测能力。预测模块不重新处理原始动态点云，而是消费 tracker 已经稳定维护的目标 ID、类别、运动模型、模型原生状态及协方差和历史快照，输出未来 1-3 秒内物体中心的预测轨迹、轨迹概率分布和 RViz 可视化。

预测结果后续会服务 LDOP 第四阶段规划地图或动态风险层，因此 LDOP 第三阶段需要同时关注三件事：

1. 预测结果本身是否合理。
2. 预测不确定性能否随时间表达风险扩散。
3. 预测误差能否闭环反馈到不同轨迹模式的概率。

## 术语边界

本文使用三套不同层级的阶段名，后文不混用：

- `LDOP 第一/二/三/四阶段`：指系统总体路线，分别是静态层、动态目标跟踪、短时轨迹预测、规划风险层。
- `P1-P4`：指 LDOP 第三阶段内部的 predictor 实施里程碑。
- `D1-D4`：指轨迹预测分布表达的复杂度层级，从单预测分支到闭环校正概率。预测分支表示同一目标未来的一种候选走法，每条分支都有自己的轨迹、概率和不确定性。

## 输入

预测模块的输入来自 LDOP 第二阶段 tracker，而不是原始点云：

- 稳定目标 ID。
- 当前时间戳和 frame。
- 目标类别 `object_class`。
- 当前运动模型 `motion_model_type`。
- 当前模型原生状态 `model_state`。
- 当前模型原生协方差 `model_covariance`。
- bbox 尺寸。
- 过往轨迹历史，保存各历史时刻的模型原生状态及协方差快照。
- 生命周期信息，如 `age`、`hits`、`missed_frames` 和当前帧是否匹配。

本文在可视化和风险解释层可以使用“中心轨迹”“位置协方差”等术语，但预测消息层仍保持模型原生语义：每个未来采样点保存对应运动模型自己的 `model_state` / `model_covariance`。中心位置固定由 `model_state[0..2]` 派生，位置协方差由 `model_covariance` 的前三维位置子块派生。bbox 仅提供目标尺寸，用于 marker、风险膨胀或碰撞近似，不作为运动中心来源。

当前代码已经具备一个重要基础：`TrackPredictionInput` 和 `DynamicObjectTrackerFrameResult::prediction_inputs` 已在 tracker 内部存在，可作为 predictor 的直接 C++ 输入边界。后续工作应在这个边界之后新增 predictor，而不是回头修改 clusterer 或把预测数组塞进 `DynamicObject.msg`。

## 系统过程

轨迹预测按能力递进组织：

```text
动态目标历史状态 + 运动学特征
  -> 轨迹外推
  -> 航向/意图估计
  -> 目标间交互与目标-地图交互
  -> 轨迹概率分布
  -> 闭环误差评估与概率反馈
```

P1 起步版本应保持可解释、可验证。学习方法可以作为后续增强方向，但 LDOP 第三阶段首版优先用运动学和规则型交互做出稳定接口，先把预测消息、可视化和评估闭环跑通。

## 输出

LDOP 第三阶段应新增独立输出，不改变 LDOP 第二阶段当前跟踪消息语义：

- `/ldop/dynamic_object_predictions`：动态目标预测结果，建议通过参数配置话题名。
- `/ldop/dynamic_prediction_markers`：预测轨迹 RViz 可视化，建议通过参数配置话题名。
- 每个目标输出多条预测分支：
  - 预测分支概率。
  - 未来时间采样。
  - 每个采样点的模型原生状态，中心位置由状态前三维派生。
  - 每个采样点的模型原生协方差，位置协方差或风险半径只作为下游派生量。
  - 预测分支行为族和归一化有符号行为强度；第一版只使用 `BEHAVIOR_BASELINE` 表示不额外假设意图的基准轨迹外推。

轨迹预测分布表达建议按 `D1-D4` 演进：

- D1：单高斯或单预测分支，概率为 1。
- D2：简化高斯混合，少量航向/意图预测分支，概率归一化。
- D3：交互修正后的高斯混合，预测分支均值和概率受目标间、目标-地图约束影响。
- D4：概率由后续观测误差闭环校正。

## LDOP 第三阶段内部实施里程碑

### P1：轨迹外推，得到单条轨迹

目标是先建立最小可运行预测链路。

主要内容：

- 新增 predictor 模块，例如 `DynamicObjectPredictor`。
- 新增预测参数结构，集中默认值；第一版只新增 prediction horizon，采样间隔复用 `tracking_default_dt`，不新增最小速度阈值或最大预测目标数。
- 新增预测消息，表达单目标多预测分支的未来轨迹；轨迹外推单轨迹阶段先只填一个预测分支。
- 从 `TrackPredictionInput` 按 `motion_model_type` 解释预测所需运动学量；接口层不新增第二套公共状态投影。
- 对每个未来采样时间做轨迹外推：
  - 中心均值按解释后的模型状态推进。
  - 模型原生协方差按当前运动模型传播，RViz 椭球从前三维位置协方差派生。
- 不为低速或近似静止目标单独设置退化分支；预测输入已经是 tracker 确认的动态目标，轨迹外推按当前运动模型状态和协方差正常传播。
- 对短历史和漏检延续目标保留同一预测链路；漏检延续目标在 RViz 中用更低透明度表达当前观测不确定性。
- 发布预测消息和预测 marker。

预期输出：

- 每个稳定目标一条未来中心轨迹。
- 单预测分支概率为 1。
- RViz 中能看到从当前目标中心向未来延伸的预测线。

验收重点：

- 预测方向与当前运动趋势一致。
- 预测 horizon 第一版默认覆盖 1.0 秒。
- 单帧耗时可记录，预测模块不明显拖慢主循环。
- 构建通过；修改 `msg/*.msg` 后必须重新 `catkin build ldop`。

### P2：轨迹外推 + 航向/意图，得到简化 GMM 多轨迹

目标是把单一确定性轨迹扩展为少量候选意图轨迹。

主要内容：

- 基于历史轨迹估计稳定航向，而不是只依赖当前状态快照中的瞬时运动量。
- 根据类别和运动模型选择候选预测分支：
  - human 可允许更灵活的横向偏转。
  - vehicle 更偏向保持航向或小曲率转向。
  - UAV 可允许三维速度方向延续。
  - other 默认保守单峰或低权重多峰。
- 初版可以使用 3 个简化预测分支：保持、左偏、右偏；具体分支是否生成由后续航向/意图设计决定，不按低速或近似静止单独退化。
- 根据历史航向稳定性、运动强度、类别可信度和漏检状态分配预测分支初始概率。
- 每个预测分支输出独立模型原生状态轨迹和模型原生协方差。

预期输出：

- 每个目标多条候选轨迹。
- 轨迹概率构成简化高斯混合分布。
- 概率总和归一化，主预测分支应与历史运动趋势一致。

验收重点：

- 多预测分支能覆盖转向或航向不确定目标。
- 预测分支不应因速度数值较小而额外切换算法；是否发散主要由模型状态、协方差传播和后续概率约束控制。
- 预测分支数量和采样点数量可通过参数控制。

### P3：轨迹外推 + 航向/意图 + 交互，得到完整 GMM 多轨迹

目标是在多意图轨迹基础上加入交互约束，使预测更适合动态环境和规划风险表达。

主要内容：

- 目标间交互：
  - 根据未来采样点的目标间距离识别潜在碰撞或过近风险。
  - 对冲突预测分支降低概率，或对轨迹均值做轻量避让修正。
  - 对同向跟随、交叉、迎面等简单关系做规则化处理。
- 目标与地图交互：
  - 使用 LDOP 第一阶段静态地图或查询接口判断预测点是否进入静态障碍物或不可通行区域。
  - 对穿越障碍的预测分支降低概率或截断。
  - 将地图约束写成 predictor 的可选输入，避免 predictor 反向污染静态地图模块。
- 完整 GMM 输出：
  - 每个预测分支保留概率、模型原生状态轨迹和模型原生协方差。
  - 交互修正后的概率仍需归一化。

预期输出：

- 多目标场景下更合理的预测分布。
- 穿越静态障碍或明显冲突的预测分支概率降低。
- 交互计算耗时可控，适合在线运行。

验收重点：

- 目标接近或交叉时，预测概率变化符合直觉。
- 地图约束不会破坏无交互场景中的线性预测表现。
- 交互逻辑保持可解释，便于后续替换为学习方法。

### P4：闭环评估与概率反馈

目标是让预测不只是一次性输出，而是能根据后续真实跟踪结果评估和校正。

主要内容：

- 建立预测缓存，把每一帧发布的预测和后续实际 tracker 输出按目标 ID 对齐。
- 计算位置误差和位移误差：
  - ADE：平均位移误差。
  - FDE：终点位移误差。
  - 分 horizon 统计误差，如 0.5s、1.0s、2.0s、3.0s。
- 评估不确定性一致性：
  - 实际位置是否落在由模型原生协方差前三维位置子块派生的协方差椭球或风险半径内。
  - 可选使用 NLL 或近似负对数似然评估概率分布。
- 统计耗时：
  - predictor 总耗时。
  - 预测分支生成耗时。
  - 交互修正耗时。
  - marker 构建耗时。
- 根据误差反馈不同预测分支的概率：
  - 命中真实轨迹附近的预测分支增权。
  - 长期偏离的预测分支降权。
  - 对类别、速度区间和交互场景分别维护轻量统计。

预期输出：

- 预测评估日志或诊断话题。
- 各 horizon 的误差统计。
- 轨迹概率随闭环误差逐步校正。

验收重点：

- 评估不影响在线预测稳定性。
- 反馈只改变概率或轻量参数，不反向破坏 tracker 当前状态。
- 闭环指标能解释预测效果变好或变差的原因。

## LDOP 总体实现进展

已经完成：

- LDOP 第一阶段：动静态点云分割与静态地图构建。
- LDOP 第二阶段：动态点云聚类、检测、跟踪、目标类别、多运动模型 KF/EKF。
- tracker 当前输出稳定 `DynamicObjectArray`，包含目标 ID、尺寸、模型原生状态、模型原生协方差、对象类别和运动模型。
- tracker 内部已构建 `TrackPredictionInput`，为 predictor 预留完整输入。

LDOP 第三阶段内部尚未完成：

- 没有 `DynamicObjectPredictor` 或等价预测模块。
- 没有独立预测消息和预测话题。
- 没有预测 RViz marker。
- 没有轨迹外推输出。
- 没有 D2/D3 级别的 GMM 多轨迹输出。
- 没有闭环预测误差统计和概率反馈。

因此，LDOP 第三阶段下一步应从“轨迹外推单轨迹”开始，而不是直接实现交互或学习式预测。

## 验证策略

验证范围按 `AGENTS.md` 的风险匹配原则选择，不把测试作为每次改动的固定动作：

- 仅修改文档或规划：执行 `git diff --check`，必要时复扫关键术语。
- 修改 C++ 实现、参数读取或配置默认值：至少执行 `catkin build ldop --no-status`。
- 修改 `msg/*.msg`：必须执行 `catkin build ldop --no-status`，确保消息重新生成。
- 修改预测行为、接口契约、并发链路或新增测试：再执行 `catkin run_tests ldop --no-status`，并用 `catkin_test_results /home/st/ldop_ws/build/ldop` 查看结果。

本安排文档只记录规划，不修改代码或消息，因此本轮不运行构建测试。
