# 前机完整手填航点备用方案

编辑 `src/zyc_fuel_ws/src/FUEL/fuel_planner/exploration_manager/config/manual_waypoints.yaml`：

```yaml
mission:
  manual_path:
    arrive_distance: 0.25
    waypoints:
      - [1.0, 1.5, 0.8]
      - [1.0, 3.0, 0.8]
      - [2.5, 3.0, 0.8]
```

以上为格式示例，使用前替换为实际场地坐标。填写全部航点，包括最终终点，无需填写当前位置。
坐标使用前机 FAST-LIO 里程计世界系（当前为 `UAV0/camera_init`），单位米；
不能直接填写 MAVROS 局部坐标或机体相对位移，`z` 也是同一世界系内的高度坐标。

新的独立入口只启动前机手填路线规划器，控制器仍沿用原有独立启动方式：

```bash
source /home/asus/match_ws/devel/setup.bash
roslaunch autotrans_reference_bridge uav0_manual_waypoints.launch
```

原自动前沿规划入口仍为：

```bash
roslaunch autotrans_reference_bridge uav0_fuel_planner.launch
```

两个入口使用同一规划节点和话题，选择其中一个启动。修改坐标后重启手填路线规划器生效。
原入口不加载这份 YAML，并明确关闭手填模式；新入口加载 YAML 并启用手填模式。
原有六分屏/七分屏脚本继续启动自动规划入口，没有改成手填模式。
新入口沿用原来的找入口、穿门和规划开始触发流程；交接给 FUEL 后执行手填列表。
因此第一点是规划交接后的第一个目标，最后一点是整条手填路线的终点。

手填模式只执行“当前位置 → 点1 → 点2 → … → 最后一点”，不生成、选择或追加前沿目标，
不需要按前沿分组。实际里程计进入当前点的 `arrive_distance` 三维半径后才推进列表；
预测规划起点、规划失败和重规划都不会跳过该点。重启规划器会从列表开头重新开始。
空列表或全部点到达后进入现有 FINISH 流程，结束路线；不会继续自动探索或自动降落。
原有遥控器降落接管仍有效。

每次以列表中的下一个点作为轨迹段终点。手填模式跳过自动任务选点、A* 搜路、路径缩短、
直线延伸、自动短段截取，以及按地图生成的转向、绕障和脱困目标。
因此手填路线也不会自动切换到出口搜索降落任务。
原有轨迹生成、动态避障代价、地图/机体足迹检查和发布/执行检查仍运行；
共线插值和时间采样用于连续的位置、速度和加速度参考，不是新导航目标。
被障碍物阻挡或轨迹检查失败时保留当前手填点，不改发自动搜索的替代点。
