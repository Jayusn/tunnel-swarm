# 前机安全接力点策略

适用入口：`shfiles/start_uav0_dual_network_six_terminator.sh`。
该入口启用 `UAV0_SAFE_RELAY_ENABLED=true`；FUEL `exploration_node` 内部选点并发布。
前机自己的前沿选择、1.2m 局部规划及轨迹执行保持原逻辑；这些局部终点不直接成为后机接力点。

## 1—5 选点与保底

1. **实际经过**：从锁定入口后的实测里程计保存 XYZ、时间、航向、累计路程。
   经过一次即可，不要求停住、悬停或者多次往返。预测轨迹终点、插值点不进入候选集合。
2. **适合停留**：对候选点完整圆柱包络内的体素检查已知自由空间，未知/占据/越界均不合格；
   同时检查中心膨胀占据，以及已有 FAPP 动态预测对停留空间的覆盖。
   只要求新候选点自身满足停留包络；不要求沿路线前后各 0.20m 也能停留，也不检查历史连接路径。
   默认两个不同地图更新均通过才确认；这是地图确认次数，不是前机停留次数。
3. **前后机分工**：前机只确认新点本身在发布时合格，不再检查 A→B 的历史路线。
   A 始终是最新已发布点（首次为实飞入口样本），只用于间距与前后顺序；A 后来被占据不回退起点。
   后机用自己的当前位置、地图和动力学规划到 B 的路径，能否执行或弃点由后机处理。
4. **前机已让开**：前机在路线进度上越过 B 至少 1.00m，并且当前 XY 到 B 至少 1.00m，才释放。
   “障碍后”以真实路线的先后顺序定义，不依赖世界坐标 X 或机头朝向。
5. **B 不合格的保底**：继续找障碍后的合格 C；没有 C，就找 A 之后、障碍之前的合格等待点 W；
   W 也没有则不发布新点，继续保留已发布点。不降低阈值、不使用任意短轨迹末端，不发布倒退等待点。

普通点优先独立筛选：默认从 A 沿实际路线前进至少 1.00m 选取合格样本，
并满足新点自身确认与前机让开要求。其他历史样本的未知、占据或不可停状态，不会通过连接检查否决 B。
没有合格普通点时，仍执行障碍后 B/C、障碍前 W 的保底顺序，保底最低累计前进量为 0.70m。
尚未发布任何点时，首个保底点相对实测跨入口样本的最低累计前进量为 0.50m；首个普通点仍要求 1.00m。
发布首点后，后续保底点统一使用 0.70m；起点不回退，不重新启用入口的 0.50m 门槛。
即使暂时没有合格停点，实际参考路线仍每 0.25s 发布。

已发布点不再按当前地图反复确认，不因旧点或旧路线后来被占据而撤回、跳号或阻止后续选点。
每个新点的路线序号递增，ID/XYZ/实测经过时间一经发布就保持不变；不会重发一个旧点作为新的倒退目标。
没有合格新点时报告 `WAIT_NO_VALID_TARGET`；不再用 `LAST_TARGET_INVALID` 卡住前机给点。
地图或里程计超时只停止新增点，仍广播已发布点和实际参考路线，并在状态话题报告超时。
**这些已发布点表示发布时通过检查，不保证此刻仍可达或仍适合停留。** 后机仍需实时规划和避障。

## 话题与接收约定

| 话题 | 类型 | 含义 |
| --- | --- | --- |
| `/UAV0/mission/relay_waypoints` | `nav_msgs/Path` | 累计已发布离散点；发布后不撤回，前机唯一发布 |
| `/UAV0/mission/reference_route` | `nav_msgs/Path` | 实际飞过的稠密 XYZ 参考路线，普通路段也持续更新 |
| `/UAV0/mission/relay_status` | `std_msgs/String` | 发点/等待原因、累计数 `released` 与快照数 `published`；不再称为当前 `valid` 数 |
| `/UAV1/mission/relay_execution_queue` | `nav_msgs/Path` | 接收端执行队列，用于诊断；不能当成当前有效性证明 |

`relay_waypoints.header.stamp` 是前机发布器启动会话标识，**不是**目标生成时间；
顶层 `header.seq` 由 ROS 发布序号持续递增，用作快照心跳。
每个 pose 的 `header.seq` 是从 1 开始、同一会话内不变的目标 ID；`pose.header.stamp` 是实测经过时间。
同一 ID 的 XYZ 不修改。同一会话内列表只增加；未发出首点时为空，旧点不因地图更新或里程计超时消失。
参考路线的 `header.stamp` 则是最后接收的实际里程计时间。参考路线是历史观测，不是对未来飞行安全的承诺。

后机现有 `leader_safe_path_follower` 接收约定（本次只改前机，不修改或远程启动后机）：

- 普通内部点改为订阅前机快照，停止本地每隔 2.5m 自行生成点；入门、出口、降落任务交接保持原流程。
- 必须收到两个连续递增快照才能启用，避免仅凭旧锁存消息执行；快照中断超过 1s 或活动点无效时保持等待。
- 普通接力点保留 XYZ，仅做两机坐标变换，不再按 yaw 后移 1m、不再强制改成 0.60m 高度。
  入队前仍保留原有双机实时 XY 间距至少 1m 的门槛。
- 后机 Diff 规划失败时重试同一个合格目标，不降级为未检查的短子目标，不自动跳过失败点。
  Diff 若把终点投影到与原合格点相差超过 0.03m 的位置，也不会将该投影点当作安全停点。
- 发布器会话变化或同一 ID 被改写时不自动重放队列，需要按任务启动流程重新初始化。

**后机必须同步并编译这版接收器。** 旧版仍会自行选点、改坐标，而且会向前机同名话题发布，不能与新版混用。
本次前机变更不新增后机自动弃点机制；现有后机规划失败仍重试同一目标，不应误认为已经实现自动跳点。
本次没有远程启动飞机或改变正在运行的飞控会话。

## 参数

文件：`src/zyc_fuel_ws/src/FUEL/fuel_planner/exploration_manager/config/safe_relay.yaml`。
参数位于 `/exploration_node/mission/safe_relay`。

- 普通点间距 `normal_spacing=1.00m`，最低累计前进量 `minimum_progress=0.70m`；两者均按实测三维路线累计长度计算，不是相邻点的水平直线距离。
- 首个保底点相对入口的最低累计前进量 `entrance_minimum_progress=0.50m`，只在没有已发布点时使用；其余安全确认与前机让开条件不变。
- 当前停留包络 `hold_radius=0.30m`、`hold_half_height=0.10m`，即水平半径 0.30m、垂直上下各 0.10m。
  这些值是选点检查范围；修改机体包络或后机到点容差时，需要一起核对。
- 已移除前机接力点的 `transit_radius`、`transit_half_height`、`maximum_sample_gap` 参数；本模块不再审核历史通行路线，不影响前机自身运动规划器的避障参数。
- 地图超时 1s，里程计超时 0.5s，历史最多 10000 个实际样本，达到上限停止新增目标并报告状态。
- `dynamic_wait_horizon=2s` 对已有 FAPP 观测执行停留检查，即使规划器启用了软动态代价优先模式也检查。
  预测模型、预测上限和观测保留时长沿用 FAPP；它不能证明未来到达时动态障碍一定不会出现。

本策略只承诺“实飞证据 + 当前地图/预测检查通过”的选点条件，不能替代后机自身实时避障、
两机坐标标定、制动距离验证和飞行测试。地图不知道的空间不会被当成安全保底点。

## 编译与检查

```bash
cd /home/asus/match_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
cmake -S src -B build
cmake --build build --target exploration_node leader_safe_path_follower \
  safe_relay_policy_test safe_relay_publisher_test leader_safe_relay_test -j2
devel/lib/exploration_manager/safe_relay_policy_test
rostest exploration_manager safe_relay_publisher.test
rostest exploration_control leader_safe_relay.test
```

飞行前观察 `relay_status`：`NORMAL` 是满足普通点间距且自身检查合格的实测样本；
`AFTER_OBSTACLE` 是障碍后保底，
`BEFORE_OBSTACLE_WAIT` 是障碍前保底，`WAIT_NO_VALID_TARGET` 表示没有新增合格点。
`STALE_MAP`、`STALE_ODOMETRY` 时停止新增点，但保留已发布点；不再发布 `LAST_TARGET_INVALID`。
`published` 只表示当前发送的点数，不能作为旧点当前安全性的证明。
