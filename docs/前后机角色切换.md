# 本机前后机角色切换

本工作空间同时编译两套角色，默认继续使用后机入口。切换前在各分屏中按 Ctrl+C 停止当前流程，再关闭窗口、启动另一入口；不需要切分支或重新编译。脚本中的 `stop` 只关闭对应 Terminator 窗口，不能代替停止 ROS 节点。

## 启动命令

在本机 Ubuntu 图形桌面终端中执行：

```bash
cd /home/oem/match_ws
# 默认后机：连接原前机 .14，执行双机接力、检测和降落。
bash shfiles/start_uav1_six_terminator.sh
```

```bash
cd /home/oem/match_ws
# 前机：本机 .21 提供 ROS master，以 UAV0 身份运行正式探索接力流程。
bash shfiles/start_uav0_dual_network_six_terminator.sh
```

前机第一屏启动或复用本机 master，并启动 MAVROS；其他分屏启动 MID360、FAST-LIO、视觉位姿、降落板搜索、FUEL/Diff 和前机 NMPC。正式前机入口保留原前机的接力点发布、出口穿越和搜索降落流程；颜色、二维码、热成像及其目标上报默认关闭。

| 模式 | ROS_IP | ROS_MASTER_URI | 逻辑身份 |
| --- | --- | --- | --- |
| 后机（默认） | 192.168.43.21 | http://192.168.43.14:11311 | UAV1 |
| 前机 | 192.168.43.21 | http://192.168.43.21:11311 | UAV0 |

前机模式下，其他参与机器应连接 `.21` 的 master，并使用各自真实的 ROS_IP；同一 ROS 网络中只运行一套 UAV0 业务。本次没有修改原前机，也没有把原前机自动切换为后机。原有后机单机航点入口 `start_uav1_seven_terminator.sh` 继续保留。

## 参数和源码

- 后机使用 `payload_mpc_controller/config/mpc.yaml`，保留当前用户调参。
- 前机使用 `payload_mpc_controller/uav0/config/mpc.yaml`，按用户最终选择保留原前机整份 MPC 参数，包括推力系数、悬停比例、权重及约束；不加载后机 MPC 参数覆盖它。
- 两种角色都使用本机 `payload_mpc_controller/config/model.yaml`（当前质量 1.926 kg）、本机雷达配置和 FAST-LIO，以及本机串口和相机标定。下视外参及中心补偿分别读取 `precision_landing/config/down_camera_extrinsic_uav1.yaml` 和 `exploration_control/config/center_offset_uav1.yaml`。
- 前机不同的控制、规划、检测和降落源码在所属包的 `uav0/` 中，目标及库使用 `_uav0` 后缀；相同源文件继续共用，涉及不同依赖库时分别编译。后机目标和消息接口保持原名。
- 前机偏航轨迹使用 `quadrotor_msgs/PolynomialTrajUav0`，后机继续使用原来的 `PolynomialTraj`。不会要求原前机为了本次本地接入更新消息或代码。
- 源码快照与原文件校验值记录在 `uav0_role_source.json`，包含采集时前机尚未提交的探索代码。

## 构建与验证

两套角色的可执行文件均位于当前工作空间 `devel/lib`。前机额外需要 FUEL 依赖包；构建时应保留当前工作空间的包白名单，并包含 `fuel_plan_env`、`bspline`、`fuel_path_searching`、`active_perception`、`bspline_opt`、`fuel_traj_utils`、`plan_manage`、`exploration_manager`、`lkh_tsp_solver`、`poly_traj`、`odom_visualization`、`pose_utils`、`waypoint_generator`。

工作空间 `src/CMakeLists.txt` 复用标准 catkin 入口，并将共用的 `waypoint_generator` 目标设为 C++14，以兼容本机 ROS Noetic/Boost；前机独立目标也使用 C++14。

不启动硬件的配置验证：

```bash
source /opt/ros/noetic/setup.bash
source devel/setup.bash
python3 shfiles/tests/test_role_configuration.py
```

轨迹桥接测试仅启动合成数据的桥接节点，使用 rostest 自己创建的独立 master：

```bash
ROS_IP=127.0.0.1 ROS_MASTER_URI=http://127.0.0.1:11461 \
  rostest autotrans_reference_bridge role_bridge.test
```

编译、launch 解析和合成数据测试不能代替实际飞行验收。本次不自动解锁、不切换 OFFBOARD、不发起真实飞行任务。

2026-10-26 验证结果：主工作空间构建成功，33 个前机可执行文件/库的时间晚于各自源码依赖；前后机目标链接未交叉混用。4 项配置测试覆盖两种角色完整 launch 的节点解析、传感器 TF、独立 MPC 参数、控制输出连接和后机配置往返一致性；独立 master 下轨迹桥接测试、3 项前机偏航轨迹输入测试、6 组 FUEL 策略测试及 55 项后机控制器回归测试均通过。旧后机回归测试的窗口就绪时刻由写死 20 个样本改为读取 `max_queue`，适配当前 30 个样本的调参，不改变控制器行为。
