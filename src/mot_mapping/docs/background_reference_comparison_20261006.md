# 5 Hz 纯雷达静态背景差分与动态目标重检对照

本轮针对狭窄通道内的小型动态障碍物，保持纯雷达、5 Hz、3 帧确认和真实目标最小直径 20 cm。20 cm 是目标物理尺寸；稀疏点云只覆盖部分表面，因此没有按点簇包围尺寸小于 20 cm 删除目标。累计框观测是跨帧重复计数的静止包代理指标，不能直接等同于人工标注的真实误检率。

## 验收结果

严格目标是静止包从当前推荐组合的 730 框降到不超过 73 框，并覆盖 467 个冻结输出时刻；快摆、慢摆、另一段分别达到至少 48/53、54/59、43/47；不能丢失超过 4 个当前动态命中。

30 组原速回放（基线，以及 A、B、A+B 各 3 组参数、每组 3 段录包）全部结束。静止结果如下：

| 基线 | — | 730 | 467/467 | 0% | A、B 均关闭 |
| A03 | 3 cm / 50% | 67 | 467/467 | 90.82% | 仅静态背景抑制 |
| A04 | 4 cm / 50% | **53** | 467/467 | **92.74%** | 仅静态背景抑制 |
| A05 | 5 cm / 70% | 58 | 467/467 | 92.05% | 仅静态背景抑制 |

A04 按“静止框更少、原有命中损失更少、最差分段召回更高”的顺序成为最终候选。它满足静止框门槛和 467 个时刻覆盖；B 会把冻结背景中的静态返回重新交给运动证据，导致静止框显著增加，不推荐打开 B。

A04 单独串行复跑的最终指标为：静止 53 框、下午包 104 个命中（快摆 45/53、慢摆 59/59）、另一段 38/47，原有命中损失 0。四个输出话题逐帧通过时间戳、数量、有限值、非负尺寸、Marker ID 唯一性、框/状态/轨迹几何核验。各段四阶段处理耗时逐帧求和的 p95/最大值为静止 74.9/90.9 ms、下午 74.2/98.1 ms、另一段 79.5/113.7 ms，均低于 5 Hz 的 200 ms 间隔；节点 HWM 分别为 123772、127136、132160 kB。

本轮没有同时达到“静止减少 90%”和“三段动态检测率均超过 90%”：A04 的快摆为 84.9%，另一段为 80.9%；B/A+B 虽各恢复 1 个动态标注，但仍只有 86.8% 和 83.0%，并且 B 增加静止框。该结论限定于本轮冻结录包和回归样例；不宣称全场景 90% 检测率，也不把累计框下降称为真实误检率下降。

## 实现

### A：启动静态背景参考

启用 `background_reference/enabled` 或 B 时，节点以首个注册云时间戳为起点采集 5 秒原始注册点云，使用世界坐标中的有限点建立一次冻结 KD 树；冻结后不再把后续运动目标加入背景。预采期间沿用原检测逻辑并发布，输出仍计入统计。

每个当前密集簇只做背景覆盖查询，不改变当前聚类输入。达到距离和比例门槛的簇，在原关联、运动记录完成后抑制当帧发布，避免用背景剔除破坏真实目标的启动关联。A03/A04/A05 分别使用 3 cm/50%、4 cm/50%、5 cm/70%。

### B：背景参考运动证据与短断轨

启用 `detection/reference_motion_enabled` 时，未被冻结背景解释的候选可以作为运动启动证据，但仍需三次实际观测、6 cm 位移、0.14 m/s 实测速率及原有新点比例门槛；没有预测点单独发布。最近 0.6 秒确实发布过的轨迹允许一个输入回调缺失后保留观测历史，重现观测时仍要求当前候选和运动确认。连续轨迹原有 0.82 m 配对、一对一匹配、换向支持和六点稀疏目标行为保留。

新增 launch 参数及默认值：

- `background_reference_enabled:=false`
- `reference_motion_enabled:=false`
- `background_reference_capture_duration:=5.0`
- `background_reference_distance:=0.03`
- `background_reference_fraction:=0.5`

两个试验开关彼此独立，默认关闭；话题、消息和四路输出接口不变。现有 `geometry_enabled`、`depth_evidence_enabled` 也继续默认关闭。

## 漏检诊断与回归

冻结的 17 个基线漏检中，15 条含少于三次实际观测；其余涉及启动运动证据不足、候选分裂/邻近候选竞争、以及一条云和里程计存在但同步输出缺失的情况，原因有重叠。B 仅在下午和另一段各恢复 1 条，未改变前三帧观测不足导致的主要漏检。在不放宽三次实际观测约束的前提下，本轮没有证据宣称动态召回已经超过 90%。

通过的回归覆盖 20 cm 六点球面可见目标、六点平面目标、径向运动、往复换向、贴墙运动、遮挡后重现、墙面碎片竞争、无人机平移/转动、启动采集结束后的首检和一帧断轨重检；两帧断轨不会绕过三帧确认。默认配置和 A04 配置的完整感知回归、5 Hz 确认回归、launch 参数解析均通过。

A04 作为可选试验配置的启动示例：

```bash
roslaunch mot_mapping uav1_detection.launch \
  background_consistency_enabled:=true \
  background_consistency_post_association:=false \
  background_local_planes_enabled:=true \
  background_local_post_association:=true \
  background_consistency_fraction:=0.55 \
  shape_consistency_enabled:=true \
  motion_displacement:=0.06 min_motion_speed:=0.14 \
  min_motion_novel_fraction:=0.26 tracked_motion_novel_fraction:=0.20 \
  background_reference_enabled:=true \
  reference_motion_enabled:=false \
  background_reference_capture_duration:=5.0 \
  background_reference_distance:=0.04 \
  background_reference_fraction:=0.5
```

该命令是试验配置，不改默认行为。默认启动保持 5 Hz、3 帧、8 cm、0.15 m/s、30% 新点和两个新开关关闭。由于本轮动态双 90 门槛未通过，A04 不写入默认 launch。

主工作空间 `mot_mapping` 已重新构建，实际 `devel/lib/mot_mapping/mapping_node` 与最终 A04 回放使用的二进制一致；launch XML 解析通过。最终回放、输入 SHA-256、逐时刻指标、内存、输出核验脚本和 10 组矩阵结果保存在 `.fapp_ball_debug/background_reference/`，该目录为本地验证产物。

参考实现：[HKU-MARS dyn_small_obs_avoidance](https://github.com/hku-mars/dyn_small_obs_avoidance)。本轮只借鉴点云/KD 树和动态重检思路，没有引入类别识别或完整 M-detector。
