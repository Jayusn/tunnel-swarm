# UAV1 连续滚动短段规划

## 运行行为

UAV1 正式 Diff 接力入口 `run_uav1_relay_diff.launch` 默认使用 `route_segment_count:=3`、`route_segment_min_length:=0.60`（米）。正式 AutoTrans 启动中 `enable_planner:=true` 引入该入口。通用 `advanced_param_exp.xml` 默认 count=1，其他入口不自动启用；原有专用 two-piece entry 模式仍走其已有实现。

保留最终任务目标。第一次为该目标搜索地图路线，以路线长度的约 1/3、至少 0.60 m 固定本目标的局部跨度。每次重规划重新搜索当前地图，只截取前方这一跨度参与局部轨迹优化。余程不再每次除以三，避免越接近目标段越短。短路线可能只需一段；周期更新可能发布多于三条轨迹，“三段”是初始空间跨度，并非恰好三次发布。

中间段终点按路线切向保留配置速度，最终目标速度为零；初始位置、速度、加速度沿用现有计划起点，常规更新仍从当前轨迹接续，跟踪偏离请求仍从实际里程计重算。沿用现有周期及接近段末触发，正常情况下连续通过中间端点，不新增停车等待流程。求解失败等异常仍执行原有处理，不能保证异常情况下也不停。

## 优化与障碍处理

初值沿地图搜索路线取点，最多每 0.30 m 一个多项式段（与路线滚动跨度不同），不直接将起终点直连。每次只优化当前短段，对整段使用已有障碍约束、地图膨胀和碰撞检查，而不是只约束非终段的前 2/3。未更改障碍膨胀半径或净空代价参数。

周期重规划的局部终点向前移动超过 5 cm 时，不用旧余程与新段的长度/jerk 比值拒绝新段（两者终点不同，不是同一段的优化质量对比）；终点相同时沿用原质量门控。候选没有替换成功时，保留实际执行轨迹对应的端点状态。未新增状态机、恢复流程或额外距离拦截阈值。

局部维数减小不等于总耗时必然变短：仍需搜索至最终目标，搜索和优化各使用现有计算预算。实际耗时、净空和跟踪效果需在相同地图/路线条件下验证，当前不宣称已经改善实飞。

## 控制器同步修复

最新 `20261021_194515__unlabeled__comp_on` 包内，5 个跟踪重规划请求均有返回，但控制器没有接替确认。旧版本使用 `Header.seq` 保存请求编号，ROS 发布时覆盖该字段，破坏了两端匹配。

请求/结果现增加独立 `uint32 request_id`，规划器回传原 ID 和请求时间；控制器两者同时匹配后才接收。保留 10 cm 持续 0.1 s 重规划、15 cm 清除旧队列，以及现有 HOLD/中止优先级。增加真实 ROS 发布订阅测试，检查消息头序号被改写后仍能接替。此前只直接调用回调的测试没有覆盖这一传输问题。

由于消息 MD5 改变，需要在地面一起重启 UAV1 规划器和控制器，使用当前主工作空间 devel。没有自动重启运行中的飞行节点，没有远端部署。默认仍为窗口外力估计，Z 实际补偿增益仍为 0；用户已有 MPC 配置修改保留且不随本任务提交。
