# UAV0原地起飞精降测试

这是实飞入口。结束手持标定，把飞机放在地面码中心上方后再开始。
停止占用下视相机的中心观测入口及其11440端口ROS；此测试使用正常飞行ROS master。
不要同时运行比赛规划器、AutoTrans控制器或其他精降节点，避免并行发送飞行目标。

推荐一键启动（图形桌面终端，只运行一次）：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_inplace_landing_test.sh
```

自动打开六个分屏：MAVROS、MID360、FAST-LIO、位姿回传、起飞/精降待命、下视画面。
各分屏统一使用既有 UAV0 飞行网络配置（默认 10.224.119.212:11311）。
启动脚本不会自动起飞。飞机放稳、定位正常且遥控可接管后，在另一个终端执行：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_inplace_landing_test.sh start
```

**start 会切换 OFFBOARD、解锁并执行起飞降落。** 等待期间可观察第 5 屏输出；
需要中止实飞时使用遥控模式接管。落地并上锁后，分别在运行节点的分屏 Ctrl+C 结束。
以下为手动分步启动方式，与一键入口二选一，不要重复运行。

需要正常运行四项基础链路：UAV0 MAVROS、MID360驱动、FAST-LIO、视觉位姿回传。
可分别在四个终端使用既有入口的单独面板命令（不要启动整套比赛流程）：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_six_terminator.sh --pane mavros
bash /home/asus/match_ws/shfiles/start_uav0_six_terminator.sh --pane mid360
bash /home/asus/match_ws/shfiles/start_uav0_six_terminator.sh --pane fastlio
bash /home/asus/match_ws/shfiles/start_uav0_six_terminator.sh --pane pose
```

各终端使用相同的正常飞行ROS网络配置；不要沿用手持观测的11440端口。

启动相机、精降和待命的起飞任务，允许显式调用start服务，但禁止自动起飞：

```bash
source /opt/ros/noetic/setup.bash
source /home/asus/match_ws/devel/setup.bash
rosrun precision_landing start_landing_test.sh allow_arming:=true auto_start:=false takeoff_height_m:=1.70
```

可另开终端观察：

```bash
rqt_image_view /UAV0/landing/debug_image
rostopic echo /landing_test/status
```

飞机已放稳、定位正常、现场允许实飞且遥控可接管时，才执行下面这一条。
**它将进入OFFBOARD并解锁、起飞，不是只启动检测：**

```bash
rosservice call /landing_test/start "{}"
```

流程：预发送2秒目标 → OFFBOARD → 解锁 → 保持开始时的XY和航向，
升至相对起点1.70米（到点高度容差0.05米、XY容差0.20米、稳定0.10秒）
→ 发布精降触发 → 精降接管后起飞节点停止发送位置目标。
精降使用当前UAV0中心补偿，到约1.2米保持高度，修正后误差≤12厘米
持续0.5秒后锁XY；再以0.10 m/s降低Z目标，约0.3米切AUTO.LAND。
高度1.70米是相对起飞时定位Z，不是绝对世界Z；平地码应靠近起飞地面高度。
水平视觉纠偏会移动飞机，因此“原地测试”不代表全程严格固定XY。

脚本默认仍不允许解锁、不自动开始；上述命令显式启用解锁权限。
`/landing_test/abort`不作为精降接管后的可靠停止方式；需要停止实飞时使用遥控模式接管。
运行日志在 `~/target_reports/landing_tests/`。本入口无搜索、前视提示或规划指令仲裁。

## 锁点后由AutoTrans/NMPC下降的独立对比测试

先结束旧测试，落地并上锁后，在桌面终端启动：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_inplace_landing_test.sh --nmpc
```

准备好后仍使用同一开始命令：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_inplace_landing_test.sh start
```

起飞、视觉对准、中心补偿、1.2米/12厘米/0.5秒锁点条件保持原样。
锁点后转发同一个固定XY、递减Z的位置目标给AutoTrans；控制器按接管时的
MAVROS本地位姿与FAST-LIO位姿建立固定平移/偏航转换，避免直接混用两个坐标系。
与AutoTrans原有降落一致，此测试下降阶段关闭外力补偿。
收到控制器有效输出后，路由节点停止转发精降的PX4位置指令，只转发NMPC输出
（求解异常时使用控制器已有的PX4恢复位置输出）。未收到NMPC输出前仍是PX4下降，
因此必须查看下面的话题或第5屏日志，确认本次确实由NMPC执行：

```bash
rostopic echo /UAV0/landing_test/descent_owner
```

`PX4`表示尚未交接，`NMPC`表示已经交接，`STOPPED`表示退出OFFBOARD/解锁状态后停止。
近地0.3米仍由原精降节点请求AUTO.LAND；切换飞控模式后不会自动重新接管。
NMPC接管后，CH10低到高可触发其原有原地降落；锁点前仍是原独立测试，
不能依赖CH10，需使用遥控飞控模式切换接管。不要同时启动另一套AutoTrans或比赛流程。
NMPC数据由现有logger记录到`~/.ros/autotrans_mpc_logs/`，精降日志仍在
`~/target_reports/landing_tests/`。不带`--nmpc`保留原PX4测试方式，总流程默认不启用此测试模式。
该入口经过编译和隔离ROS模拟输入验证，尚未验证实飞落点是否改善。
