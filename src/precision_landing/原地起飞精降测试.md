# UAV0原地起飞精降测试

这是实飞入口。结束手持标定，把飞机放在地面码中心上方后再开始。
停止占用下视相机的中心观测入口及其11440端口ROS；此测试使用正常飞行ROS master。
不要同时运行比赛规划器、AutoTrans控制器或其他精降节点，避免并行发送飞行目标。

推荐一键启动（图形桌面终端，只运行一次）：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_inplace_landing_test.sh
```

自动打开六个分屏：MAVROS、MID360、FAST-LIO、位姿回传、起飞/精降待命、下视画面。
各分屏统一使用既有 UAV0 飞行网络配置（默认 10.224.119.212:11311）。
启动脚本不会自动起飞。飞机放稳、定位正常且遥控可接管后，在另一个终端执行：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_inplace_landing_test.sh start
```

**start 会切换 OFFBOARD、解锁并执行起飞降落。** 等待期间可观察第 5 屏输出；
需要中止实飞时使用遥控模式接管。落地并上锁后，分别在运行节点的分屏 Ctrl+C 结束。
以下为手动分步启动方式，与一键入口二选一，不要重复运行。

需要正常运行四项基础链路：UAV0 MAVROS、MID360驱动、FAST-LIO、视觉位姿回传。
可分别在四个终端使用既有入口的单独面板命令（不要启动整套比赛流程）：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_six_terminator.sh --pane mavros
bash /home/asus/match_ws/shfiles/start_uav0_six_terminator.sh --pane mid360
bash /home/asus/match_ws/shfiles/start_uav0_six_terminator.sh --pane fastlio
bash /home/asus/match_ws/shfiles/start_uav0_six_terminator.sh --pane pose
```

各终端使用相同的正常飞行ROS网络配置；不要沿用手持观测的11440端口。

启动相机、精降和待命的起飞任务，允许显式调用start服务，但禁止自动起飞：

```bash
source /opt/ros/noetic/setup.bash
source /home/asus/match_ws/devel/setup.bash
rosrun precision_landing start_landing_test.sh allow_arming:=true auto_start:=false takeoff_height_m:=1.70
```

可另开终端观察：

```bash
rqt_image_view /UAV0/landing/debug_image
rostopic echo /landing_test/status
```

飞机已放稳、定位正常、现场允许实飞且遥控可接管时，才执行下面这一条。
**它将进入OFFBOARD并解锁、起飞，不是只启动检测：**

```bash
rosservice call /landing_test/start "{}"
```

流程：预发送2秒目标 → OFFBOARD → 解锁 → 保持开始时的XY和航向，
升至相对起点1.70米（到点高度容差0.05米、XY容差0.20米、稳定0.10秒）
→ 发布精降触发 → 精降接管后起飞节点停止发送位置目标。
精降使用当前UAV0中心补偿，到约1.2米保持高度，修正后误差≤12厘米
持续0.5秒后锁XY；再以0.25 m/s降低Z目标，约0.3米切AUTO.LAND。
高度1.70米是相对起飞时定位Z，不是绝对世界Z；平地码应靠近起飞地面高度。
水平视觉纠偏会移动飞机，因此“原地测试”不代表全程严格固定XY。
锁XY前反复丢码时，悬停高度目标不会随飞机上浮而抬高；实际下降后可更新到更低高度。
该规则由总流程和独立测试共用，丢码时仍暂停视觉下降并等待重新识别。

脚本默认仍不允许解锁、不自动开始；上述命令显式启用解锁权限。
`/landing_test/abort`不作为精降接管后的可靠停止方式；需要停止实飞时使用遥控模式接管。
运行日志在 `~/target_reports/landing_tests/`。本入口无搜索、前视提示或规划指令仲裁。

## 全程AutoTrans/NMPC独立对比测试

先结束旧测试，落地并上锁后，在桌面终端启动：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_inplace_landing_test.sh --nmpc
```

准备好后执行同一开始命令（会解锁起飞）：

```bash
bash /home/asus/match_ws/shfiles/start_uav0_inplace_landing_test.sh start
```

此模式由NMPC执行起飞、视觉对准、边下降边纠偏以及锁定XY后的下降。
中心补偿、1.2米/12厘米/0.5秒锁点条件保持不变。解锁前只向PX4预发送当前
位置以建立OFFBOARD；解锁后将起飞高度目标在5秒内递增交给NMPC（1.7米对应0.34 m/s），实际到达1.7米后
由原任务触发精降。未收到NMPC输出前只保持当前位置，不回退到PX4执行起飞或视觉纠偏。
精降的位置目标、水平速度加高度保持、三轴速度下降均转换成NMPC参考；
速度参考积分为连续位置并保留速度前馈，超时则保持最后参考位置。
控制器在开始接管时根据MAVROS与FAST-LIO位姿确定固定平移和偏航转换。
飞控State心跳约1 Hz，转发器使用1.5秒状态超时，避免每秒后半段中断目标和控制输出。
目标和控制消息仍要求0.3秒内有效；收到退出OFFBOARD或上锁状态会立即停止输出。
本独立测试全程关闭外力补偿，不修改总流程的补偿开关。

可观察：

```bash
rostopic echo /UAV0/landing_test/descent_owner
```

`WAITING_NMPC`表示尚未交接，`NMPC`表示已交接，`TOUCHDOWN_DISARMING`表示已确认接地并请求上锁，`LANDED_DISARMED`表示飞控已上锁。
`STOPPED`表示其他模式退出。
正常精降在距锁点时估算的码平面0.30米时请求AUTO.LAND；此前由NMPC执行下降。
飞控确认切入AUTO.LAND后，转发器停止MPC输出，由飞控完成接地及落地上锁。
CH10原地降落在距起飞参考平面0.30米时请求AUTO.LAND，并恢复原有8秒超时切换。
模式请求未确认前仍持续输出控制目标；退出OFFBOARD后不会自动重新接管。
求解/定位异常仍保留控制器已有的恢复机制。
NMPC从起飞接管后，CH10低到高可触发其原有原地降落；待命阶段CH10不会触发起飞。
不要同时启动另一套AutoTrans或比赛流程。NMPC数据记录到`~/.ros/autotrans_mpc_logs/`，
精降日志在`~/target_reports/landing_tests/`。
不带`--nmpc`仍为原PX4测试方式，总流程不启用此测试模式。
编译和隔离ROS模拟输入通过不代表实飞落点已改善，需要现场对比。

## UAV0 总流程接入（2026-10-14）

`shfiles/start_uav0_six_terminator.sh`（含调用它的双机网络入口）已启用当前版本的 MPC 精降。
沿用总流程起飞、FUEL 探索和搜索降落流程；收到 `need_to_land` 且精降开始输出后，
仲裁器把视觉纠偏、定高和锁点下降目标发到 `/UAV0/landing/nmpc_target`，由已运行的
AutoTrans 执行，不另启控制器，也不运行独立测试的起飞任务。

总流程与独立测试共用中心补偿、视觉纠偏及锁点算法：码相对高度到 1.2 m、
水平误差不超过 0.12 m 且连续保持 0.5 s 后，锁定当前 local XY；
随后按定位高度下降，距锁点时估计的码平面不超过 0.3 m 时切 `AUTO.LAND`。
`CH10` 仍优先打断精降，执行总流程原有的遥控降落逻辑。

总流程控制器启用 `precision_landing_mission_mode:=true`，检测/精降启动链启用
`landing_via_mpc:=true`，启动脚本已配套传入。旧的简单控制器入口默认保持原模式。
控制器姿态及恢复位置输出都经过仲裁器；精降原始目标不再同时直发飞控。
修改后需要重新启动总流程的控制器和检测/精降进程，不会热更新已运行节点。

验证使用隔离 ROS master 和模拟传感器：覆盖触发前不接管、飞行中交接、坐标转换、
三种目标类型、CH10 优先以及退出 OFFBOARD 后停止输出；不代表已完成总流程实飞验证。

### 前机 MPC 定位统一为 FAST-LIO（2026-10-14）

前机 MPC 总流程及 `start_uav0_inplace_landing_test.sh --nmpc` 的起飞、精降姿态、
锁点 XY、下降高度及近地判定统一读取 `/UAV0/fast_lio/Odom_high_freq`。
`fast_lio_pose.py` 仅转换 Odometry 为 PoseStamped，保留原始位姿、frame_id 和时间戳，
输出 `/UAV0/landing/fast_lio_pose`。锁定的是满足对准条件时的 FAST-LIO 当前 XY。
MPC 直接使用同一坐标系目标，不再应用 PX4 local 到 FAST-LIO 的转换。

OFFBOARD 待命预流以及故障恢复的 PX4 位置接口仍使用飞控 local 坐标；
不能把 FAST-LIO 位置原值直接发送到 PX4 本地位置接口。
近地仍切 AUTO.LAND，CH10 优先级和锁定阈值保持原样。
旧的非 MPC 直连飞控入口保持原坐标接口。本次不修改后机。
