# UAV1 性能诊断日志

`start_uav1_seven_terminator.sh` 调用的 `run_uav1_sensor_stack.sh fastlio` 自动传入
`performance_logging:=true`。直接使用 `mapping_mid360.launch` 时默认关闭，
可通过同名 launch 参数开启/关闭。参数在启动时读取，不会重启已有节点。

## 日志位置

- FAST-LIO：ROS 日志目录中的 `fastlio_timing_<PID>.csv`，终端启动信息会打印完整路径。
- 系统资源：`~/.ros/log/<run_id>/resources_<PID>.jsonl`；设置 ROS_LOG_DIR 时使用该目录。
- 发生异常后保留整个 ROS 日志目录，以及对应的诊断 bag、AutoTrans bag。

## 耗时 CSV

使用单调时钟测量，单位毫秒，`wall_time` 是本轮结束时系统时间（秒），
`lidar_stamp` 是点云结束时间（秒）。每帧一行；无点云但耗时或轮间隔超过
20 ms 的循环也记录（lidar_stamp=0）。普通空闲循环不写入。

依次记录回调处理、数据同步、IMU 处理、地图裁剪、降采样、地图初始化/准备、
原有 debug 文件写入、匹配优化、预测状态更新及里程计发布、地图增量更新、
点云/路径发布、剩余工作（含 rate.sleep）。匹配阶段也包括原有的匹配准备工作。
`loop_gap_ms` 为连续两轮开始时间间隔，包含上一轮处理耗时；
`previous_log_ms` 为上一次写诊断日志的耗时，用来观察诊断本身的写入影响。
初始化、早退循环通过作用域退出记录，未完成阶段的耗时归入 tail。

使用 64 KiB 缓冲，最多每秒主动刷新一次，无逐帧终端打印。
正常退出关闭文件；强杀/掉电可能丢失最后一段缓冲。
永久阻塞且未退出的循环没有完成行，不能仅靠 CSV 判断永久阻塞的具体位置。

## 资源 JSONL

每秒一次，记录系统/各核心 CPU 累计计数、内存、换页、磁盘累计计数、
CPU/内存/IO 压力，以及当前用户进程的 CPU、RSS、缺页、IO 累计计数。
FAST-LIO、FAPP、规划器、rosbag 另记录线程计数和等待位置 wchan。
不保存完整命令行或环境变量。每 5 次主动刷新，正常退出关闭文件。

首行说明时钟 tick 和页面大小；后续相邻样本作差计算速率，按
PID + start_ticks 区分进程重启。CPU 100% 代表一个逻辑核心。
`sample_ms` 是读取资源信息的耗时（不含序列化/写日志）。
这只是被动记录，不增加急停、拦截或恢复逻辑。

## 本次验证

- 主工作空间 fast_lio 及依赖编译通过；诊断开关的 launch 解析通过。
- 计时辅助代码测试覆盖阶段耗时、慢空闲循环、早退及 CSV 字段对齐。
- 独立 ROS 环境运行资源采样 12 次，正常退出封闭日志；平均采样约 15.6 ms，
  进程约占单核 CPU 1.8%，日志约 66 KB/s（数值随进程数量变化）。
- O2 微基准：计时辅助代码开启约 0.323 微秒/循环，关闭约 0.014 微秒/循环；
  不是完整 FAST-LIO 的性能对照，也不涵盖真实磁盘阻塞时的开销。
- 未替换正在运行的 FAST-LIO 进程；完整在线对照需在地面重新启动后进行。
